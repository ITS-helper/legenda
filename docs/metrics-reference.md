# Справочник метрик Workwatch

> Это опорный документ проекта. Все описания метрик на сайте, в письмах и в
> коде должны соответствовать определениям отсюда. Источник — официальное
> «Описание метрик Workwatch» (структура отчётов системы мониторинга).

Система формирует четыре отчёта. Основная единица данных — **минута** (отчёт 11),
из неё строятся все агрегаты.

| № | Отчёт | Гранулярность | Назначение |
|---|-------|---------------|------------|
| 6 | FaceID — по сменам | 1 строка = смена сотрудника | Посещаемость, отработанное время, график |
| 8 | LongIDLE (агрегированная активность) | 1 строка = тех. сессия | Активность / ходьба / простои за сессию |
| 10 | Длительные простои (детализация) | 1 строка = эпизод простоя | Разбор каждого простоя ≥ 5 мин |
| 11 | АА / BLE (поминутная детализация) | 1 строка = минута | Лог активности и местоположения |

Сейчас в наш проект импортируются отчёты **6, 8 и 11** (обязательные) и **10**
(опционально — если файл за дату есть в Drive). См.
[report-sources.md](./report-sources.md) и [drive-sync.md](./drive-sync.md).
Без отчёта 10 импорт остальных трёх проходит штатно, но метрики «Длительный
простой» и блок простоев на дашборде будут неполными.

---

## Базовые понятия

- **Активность (`work_sec`)** — секунды активной работы внутри интервала.
- **Ходьба (`go_sec`)** — секунды перемещения (ходьбы между зонами).
- **Простой (`idle_sec`)** — секунды бездействия / слабой активности.
- `work_sec + go_sec + idle_sec ≈ total_sec` (обычно интервал = 60 сек), поэтому
  Активность + Ходьба + Простой ≈ 100 %.
- **`real_*` vs `full_*`** (отчёт 8):
  - `real_*` — только внутри установленного графика объекта;
  - `full_*` — без учёта графика (для клинеров, где бывают ночные или вне-графиковые смены).
- **Длительный простой** — эпизод от **300 секунд (5 мин, значение из конфига)**,
  в котором `idle_sec` составляет более ~90 % времени. Порог настраивается.
- **Слабая активность** — искусственная бизнес-метрика: `idle_sec`, который НЕ попал
  в интервал длительного простоя. Технически это простой (рука неподвижна), но по
  бизнес-логике — особенность работы (напр., клинер держит швабру в ведре). В
  интервале длительного простоя может быть не ровно `60×5`, а, например,
  `51+55+54+55+55=270` — датчики ловят микродвижения (телефон, сигарета).
- **Зоны (`zona`)** — номер зоны, к которой привязан BLE-маячок. Категории по
  справочнику: рабочая, зоны отдыха, склады, уборные, мастерские, КПП и т.д.
  В данных LEGENDA: `zona = 13` трактуется как **КПП**; `zona = 1` исторически
  принималось за рабочую зону (ПВ). Точный числовой справочник зон ведётся на
  стороне системы мониторинга.

## Отчёт №6: FaceID — по сменам

**Назначение:** контроль посещаемости, учёт фактически отработанного времени и
соблюдения графика. Используется для табелирования сотрудников.

| Столбец | Тип | Описание |
|---------|-----|----------|
| Дата смены | Date | Календарная дата, на которую назначена смена |
| ID смены WW | int64 | Уникальный глобальный ID смены в системе |
| Номер | int64 | Табельный номер (ТН) сотрудника |
| ФИО | String | Фамилия, Имя, Отчество |
| Объект | String | Название объекта |
| ТН-заказчика | float64 | Табельный номер во внешней системе заказчика |
| Участок | float64 | Конкретный рабочий участок внутри объекта |
| Начальник | String | ФИО ответственного руководителя |
| Профессия | float64 | Код или название должности |
| График | String | Тип смены (напр. «Дневная/Ночная»). Не используется на клининге |
| Время получения часов | Datetime | Фактическое начало сессии (взял часы) |
| Время сдачи часов | Datetime | Фактическое окончание (сдал часы). Может быть пустым, если отчёт выгружен до сдачи |
| Итого находился в часах | Time | Длительность смены ЧЧ:ММ:СС |
| Итого находился (с) | int64 | Длительность смены в секундах |
| Смена > 18 часов | Bool | Флаг-предупреждение о сверхдлинной смене |
| ID тех. сессий | List | Список ID сессий трекера, привязанных к смене |

## Отчёт №8: LongIDLE (агрегированная активность)

**Назначение:** статистика активности, движения и простоев за сессию.

**Важно:** `real` — данные внутри графика объекта; `full` — без учёта графика
(для клинеров, где может быть несколько смен, включая ночные / вне графика).

| Колонка | Тип | Описание |
|---------|-----|----------|
| ТН | int64 | Табельный номер |
| ТН Заказчика | float64 | Внешний табельный номер |
| ФИО | object | ФИО сотрудника |
| Участок | float64 | Рабочий участок |
| Начальник | object | Руководитель |
| Профессия | float64 | Должность |
| Объект смены | object | Локация |
| date | object (date) | Дата сессии |
| date_begin | object (datetime) | Время начала смены |
| date_end | object (datetime) | Время конца смены |
| Итого находился в часах | object (time) | Общее время сессии |
| График работы | int64 | Продолжительность смены в часах (напр. 12) |
| ID смены WW | int64 | Дубль session_id |
| EUI часов | object | Уникальный аппаратный адрес (MAC/ID) часов |
| session_id | int64 | Уникальный ID технической сессии записи данных |
| full_go / real_go | float64 | **% времени ходьбы** (real — с учётом графика, full — без) |
| full_work / real_work | float64 | **% времени активности** (real / full) |
| full_idle / real_idle | float64 | **% времени простоя** (real / full) |
| full_idle_seconds | int64 | Общее время простоя, сек |
| real_idle_seconds | int64 | Время простоя, сек (с учётом графика) |
| full_go_seconds | int64 | Время ходьбы, сек |
| real_go_seconds | int64 | Время ходьбы, сек (с учётом графика) |
| full_work_seconds | int64 | Время активности, сек |
| real_work_seconds | int64 | Время активности, сек (с учётом графика) |
| full_total_seconds | int64 | Общее время записи данных, сек |
| real_total_seconds | int64 | Время записи данных, сек (с учётом графика) |
| full_long_idle_seconds | int64 | Время простоев, превышающих порог (длительные простои) |
| full_common_idle_seconds | int64 | Время обычных (коротких) простоев |
| long_data__idle_seconds | int64 | Техническая метрика длительности простоев |
| long_data__total_seconds | int64 | Техническая метрика общего времени |
| real_comon_idle | float64 | % простоя от общего (idle_sec из отчёта 11 до 300 сек) |
| real_long_idle | float64 | % длительных простоев от общего (idle_sec из отчёта 11 от 300 сек) |

## Отчёт №10: Длительные простои (детализация)

**Назначение:** построчный список каждого зафиксированного эпизода бездействия
(простоя от 5 минут) для детального разбора.

**Определение местоположения** — два параметра: `chosen_ble_tag_number` (номер BLE
маячка) и `chosen_ble_tag_zone` (номер зоны маячка: рабочая / отдыха / склады /
уборные / мастерские и т.д.).

Длительным считается простой при сессии 300 секунд (значение изменимо), где
`idle_sec` составляет более ~90 %.

| Колонка | Тип | Описание |
|---------|-----|----------|
| ID смены WW | int64 | ID смены (связь с отчётом 6) |
| session_id | int64 | ID сессии (связь с отчётами 8 и 11) |
| plan_work_begin | object (date) | Дата начала смены по плану. *Не используется* |
| ТН | int64 | Табельный номер |
| ФИО | object | ФИО сотрудника |
| dt_start | object (datetime) | Начало эпизода простоя |
| dt_end | object (datetime) | Окончание эпизода простоя |
| duration | int64 | Длительность эпизода (мин), из `idle_sec` отчёта 11; связано с long_idle отчёта 8 |
| work_type | int64 | Код типа активности. *Не используется* |
| work_code | int64 | Дополнительный код статуса работы. *Не используется* |
| chosen_ble_tag_number | int64 | Номер BLE-метки, у которой зафиксирован простой |
| chosen_ble_tag_zone | int64 | Номер зоны, в которой находится метка |
| ble_label | float64 | Текстовая метка/название зоны (если заполнено / не используется) |

## Отчёт №11: АА / BLE (поминутная детализация)

**Назначение:** поминутный лог активности и местоположения сотрудника. Каждая
строка — минута. Из этих данных строятся все отчёты, включая отчёт 10.

**Определение местоположения** — `metka` (номер BLE маячка) и `zona` (номер зоны:
рабочая / отдыха / склады / уборные / мастерские и т.д.).

| Колонка | Тип | Описание |
|---------|-----|----------|
| ТН | int64 | Табельный номер |
| user_id | int64 | Системный ID пользователя (дубль ТН) |
| ID смены WW | int64 | ID смены |
| День смены | object (date) | Дата записи |
| ID сессии | int64 | ID сессии часов |
| idle_sec | int64 | Секунд простоя / слабой активности\* (внутри минуты) |
| go_sec | int64 | Секунд ходьбы (внутри минуты) |
| work_sec | int64 | Секунд активности (внутри минуты) |
| total_sec | int64 | Длительность интервала (обычно 60 сек; меньше — на стыке смены) |
| ble_tags | object (json) | Список всех видимых BLE-меток в интервале |
| metka | float64 | ID метки с самым сильным сигналом (местоположение) |
| zona | float64 | ID зоны, к которой привязана метка |
| chosen_metka | float64 | *Не используется* (дубликат metka) |
| chosen_mapped_metka | float64 | *Не используется* |
| Дата на объекте | object (date) | Локальная дата смены |
| Время на объекте | object (time) | Локальное время (ЧЧ:ММ) активности |
| working_hours | int64 | *Не используется* |
| work_code | int64 | *Не используется* |
| sleep | int64 | *Не используется* |
| wear | int64 | Флаг ношения устройства (датчик снятия). Не используется на клининге |
| date | object (datetime) | Полный timestamp интервала (UTC+0) |

\* **Слабая активность** — см. «Базовые понятия». Пример: интервал длительного
простоя `15:56:00–16:00:59` (300 сек) — все минуты `idle_sec = 60` (100 %) →
длительный простой. А интервал `14:08–14:10` с `idle_sec = 22, 13, 4` не попадает
в длительные простои и считается слабой активностью (микродвижения при работе).

## Как это отражено в нашем проекте

| Метрика на сайте | Источник | Формула |
|------------------|----------|---------|
| Вышло на смену | отчёт 6 (shifts) | число смен за день; итого: `факт / 51`; по бригадам: Джалол `факт / 20`, ЛИ СОН ХАК `факт / 23` |
| Активность | отчёт 11 | `sum(work_sec) / sum(total_sec)` |
| Слабая активность | отчёт 11 − отчёт 10 | `(sum(idle_sec) − sum(duration_min≥10×60)) / sum(total_sec)` — остаток простоя после длительных эпизодов |
| Длительный простой | отчёт 10 | `sum(duration_min) / sum(total_sec)` для эпизодов **≥ 10 мин** (в проекте Legenda; в Workwatch по умолчанию 5 мин) |
| Ходьба между зонами | отчёт 11 | `sum(go_sec) / sum(total_sec)` |
| На КПП | отчёт 11 | время в `zona = 13`, **кроме 13:00–14:00 МСК**; в списке — интервалы по `event_at` |
| Длительность смены | отчёт 6 | `avg(on_watch_duration_seconds)` по сменам бригады за день / неделю |

**Не используются (по документу), не показывать как метрики:** `sleep`, `wear`,
`working_hours`, `work_code`, `chosen_metka`, `chosen_mapped_metka`.
